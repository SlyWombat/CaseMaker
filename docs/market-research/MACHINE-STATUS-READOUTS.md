# Live machine-status readouts ("DRO") across desktop CNC / CAM apps — 2026-10-25

Why this exists: the maintainer's bar is "the best in the category, the most intuitive UI". Before Case Maker
designs its status strip (the matrix's one ABSENT row that every bench session feels — MAKERA-VS-CASEMAKER.md,
row "DRO"), this records what each platform actually shows, with a source for each claim. Items marked
*(code)* rest on the platform's shipped open-source UI code, which is more precise than its docs; "not
established" means no source was found — do not assume.

Method: vendor docs, manuals, release notes, forums; open-source UI code where the vendor site blocked fetches.
Makera Studio's facts come from the maintainer's own screenshots in this repo (`docs/bench/img/D0-*.png`,
`D1-*.png`, 2026-10-07) and `docs/design/cnc-job-workflow.md` §A.6; Makera's wiki and manual for the Carvera
Controller. Easel / Bantam / Snapmaker help centres were read through their public endpoints.

## 3. What the evidence says

**Consumer tier (Easel, Carbide Motion, Bantam, Luban)** shows the work frame only, or no live position at all
(Bantam), hides the machine frame behind a click-toggle (Carbide Motion), an "advanced" inspector (Easel) or a
separate page (Luban); shows no state word; expresses overrides as a percentage without the resulting
feed/RPM; handles tool identity with a pre-run prompt rather than a readout; and confines the readout to a run
context. Their own users keep asking for the operator-tier features: both frames (Easel 121537, Carbide
45338), the actual feed (Carbide 19447), RPM and the current tool (Carbide 90, 64179).

**Operator tier (UGS, CNCjs, gSender, Carvera Controller / Studio)** shows both frames at once — the three
apps built for ONE machine (Studio, Carvera Controller, gSender) converged on work LARGE with machine SMALL
beneath it, per axis — 3 dp; a state element fused with the connection state; actual feed and RPM with the
override as the secondary figure; the tool taken from the machine (Carvera 1–6 / None / Probe + TLO; gSender
nicknames and probed state); and a persistent strip visible whenever the app is open. Published rationale
exists only at gSender (plain language; one place to look when something goes wrong; Zero and Go To
separated after accidental plunges) and Makera (automation hides manual control).

**Secondary points the evidence supports:** click-to-type on the work value (gSender, MASSO); progress driven by
acknowledged lines so the bar "doesn't run ahead of the tool" (CNCjs); remaining time alternating with time
until the next tool change (Carvera Controller); remaining time must track the override (standing complaints
at Carbide and Luban).

**Not established anywhere — do not assume:** Studio's state-word and connection placement and its unit
switch; Carbide Motion's state word and decimals; any live DRO in Bantam; Easel's decimals and rotary; MASSO's
frame and tool display; LightBurn's frame.
