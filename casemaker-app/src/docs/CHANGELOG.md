# Changelog

All notable changes to Case Maker. The project follows the [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format.

> **Note:** Until 1.0.0, parameter shapes are not API-stable. The `.caseproj.json` schema is versioned (`schemaVersion: 1`) and load-validated; old projects are rejected with a clear error rather than silently misinterpreted.

## [Unreleased]

### Milestone 1.5 — the bench wave: the planner's cost, the door and the run (2026-11-09)

The 2026-11-09 bench session's findings and the landings that answer them: the planner's sampling cost and memory, the door and the wizard as a way in rather than the only room, the job/cutter/run screens, and the rule that a program is stale only when something that changes its bytes has changed.

**The planner and the goal check.**

- **The row sampler's floor is a sampling spacing, not the chord tolerance** ([#1129](https://github.com/SlyWombat/CaseMaker/issues/1129)): the drop-cutter rows were handed an *acceptance* tolerance (0.005 mm) as their minimum spacing, so they subdivided to 5 µm at every kink — a 59 mm plate's plan spent 1.72 M drop-cutter queries, 57.8 M edge-search calls and 1.42 B function evaluations in 72 s and did not finish in an hour. Rows now step at the cutter's step-over / 10 (capped at 0.05 mm, never below the chord tolerance, which keeps governing acceptance; a job may state `surface.minSpacingMm`), and the edge-contact search stops once its interval is 1e-3 mm along the edge — the Z the parity fixtures and the NC judge at. The OpenCamLib/PyCAM parity fixtures still hold at 0.001 mm, row-dropper and non-circular specs stay green, and the figure card's leftover is re-pinned to the new floor.
- **A bit change is priced from the program before it, and equal cutters compete on the priced cycle** ([#1114](https://github.com/SlyWombat/CaseMaker/issues/1114)): a change costs 120 s while the program before it is at most 5 minutes, rising smoothly (3t²−2t³) to 15 return minutes from a 30-minute walk-away — four shop settings, recommendations whose thresholds rule. The plan's cycle includes every change at its price, and the sheet prints each change with its price, its standing (attended/rising/walk-away) and the program that precedes it. Ties after price go the reach-margin gate → the shortest sufficient flute → the larger diameter → the lower priced stage → the key, through ONE `pickAmongEquals` at every site (ball rank, sequence primary, curved flat, rest ball); the "by key, pending #1114" rows are gone, and set B is re-keyed to the composed rule.
- **A level pass is emitted only where the cutter's disc clears the CL above it** ([#1135](https://github.com/SlyWombat/CaseMaker/issues/1135)): a ring inset from a simplified mask could cross into a cell whose CL stands above the pass level — the organizer STEP row's wall-foot cell 0.194 mm into the goal at (79.9, 143.4), with the same class in the rough's Z-levels and its band skim. One shared rule (`safeRasterRuns`, `splitUnsafeRuns`) samples each level ring at the run's sampling spacing and returns the safe stretches as open runs; a ring with no unsafe sample comes back closed and byte-identical, so untouched plans do not move. The guard's sampling spacing and why it cannot miss a wall are stated beside it.
- **The ball rank folds and evicts each candidate's stamp** ([#1125](https://github.com/SlyWombat/CaseMaker/issues/1125)): goal coverage kept every measured candidate's exact stamp — 703.7 MiB of array buffers by `rank:end` on m1trayF-banded2, the aggregate that exhausts a 32-bit renderer — and now drops each field from the cache as it folds it: the same fold and numbers, 177.9 MiB at `rank:end`, RSS 1,186 → 688 MiB. The planner's stated memory floor follows the measurement: `PLANNER_PEAK_FLOOR_MB = 454` (the bench's Set B peak at the same stage), and the operator sentence says "about 450 MiB".
- **A 32-bit or address-limited browser is refused before planning** ([#1124](https://github.com/SlyWombat/CaseMaker/issues/1124)): the bench's plan death at sequence 35 % was a 32-bit Chrome on ARM64. `userAgentData` bitness short-circuits, and a startup probe reserves the planner's memory floor in 8 MiB chunks then releases it; the panel says which of the two happened, with two sentences under one code — "This browser is 32-bit; the planner needs a 64-bit browser", or, for a 64-bit browser whose probe failed, "This browser can't reserve the memory the planner needs (about 700 MiB); close other tabs or use a 64-bit browser". Generate is disabled while the check fails, with the same belt inside `generate()`.
- **A rotary placement that cannot be cut is stated, informed** ([#1097](https://github.com/SlyWombat/CaseMaker/issues/1097)): where the axis runs outside the body the rays meet air and the stock stands as a block, and where the surface comes inside the finishing ball's own radius no ball can cut it. Generate now states both on the goal's radial field as a `goal-rotary-unreachable` warning: the air share of the map, the share of the covered surface within 2 mm of the axis with the X spans of its components (the arc wrapping), and the share inside the finishing ball's radius with the closest approach and the ball's diameter. The panther at its stated placement: 39.5 % of the map unsampled → 0 % after the fix, closest approach 0.008 → 5.993 mm.
- **A bracket hold registers on one top touch at the cut area's centre** ([#1133](https://github.com/SlyWombat/CaseMaker/issues/1133), part 1): a bracket fixes X, Y and rotation, so the vise's 37-touch edge find is gone from the plan — with the seat measured there is no tap at all, and the datum the profile holds is the reference. The seat tap's candidate search is bounded by the machine envelope on every side, and the head envelope is height-filtered: the Z1's 46 mm carriage reading becomes a 28.5 mm head radius for the band a body must descend through to hit the stock, so a seat point in front of the blank no longer puts the head over taller wood.

**The Sample Bench.**

- **The 33 staged Google Drive samples run one bench tool** ([#1121](https://github.com/SlyWombat/CaseMaker/issues/1121)): `tools/samples/run-gdrive-samples.mts` reads the staged manifest, builds the job each purpose asks for, runs it through the CLI's own cut door (`casemaker cut … --json`) and writes `results.json` (import · plan · goal check per sample) beside the receipts under `<root>/runs/<sha>/`; the downloads never enter the repo. The harness's timeout now terminates the process that is planning (it starts `scripts/casemaker.ts` through tsx as the bin does, instead of killing a `spawnSync` wrapper and orphaning the planner).

**The door and the wizard.**

- **Load takes a cutting job, and each door tile is its own control** ([#1122](https://github.com/SlyWombat/CaseMaker/issues/1122)): a `.cutjob.json` dropped on the door or chosen with Load opens through the Job panel's own sequence — a blank project sized to the job's stock, the job set, the Job panel — while a `.caseproj.json` opens as a project as before; anything else gets one sentence, with the parse detail in the console, never a schema dump in the top bar. Open a job sits beside Load, and every capability tile is a button with hover and focus states, its inner label still the action. The crash banner reports only a marker left by THIS build.
- **The wizard is an overlay on the CNC workspace** ([#1123](https://github.com/SlyWombat/CaseMaker/issues/1123) item 2): entering CNC keeps the project and lands in the workspace, and ✕ closes the wizard without throwing the operator back to the door — Open job…, the last jobs and Start a new job are all there.
- **Step 2 passes with nothing picked** (#1123 item 3): a user who only wants to open a file gets the empty job; the amber "type the text" sentence applies once a chip that needs input is chosen.
- **The machine-change wizard offers the bracket fit** (#1123 item 9): step 1 lists Bracket at anchor 1/2 whenever the house owns a bracket record (and offers to register one), so the Cut banner's Change the machine… is no longer a dead end.
- **A narrow blank gets one default clamp, not two at one point** (#1123 item 13): `defaultClampPlacements` has a minimum-width guard, so the two clamps no longer land at the same `at` with identical labels.
- **Probe lines get a probe-length reply window by default** (#1123 item 17): the `tools/z1` harness's send defaults now match the app's `PROBE_TIMING`, so the `[PRB]` replies to M491 and G38 are captured without flags.

**The job, the cutters and the run.**

- **Long runs have a visible log, and borrowed feeds are stated on the cutter row** (#1123 items 4 and 8): a ▸ **Log** fold under the progress line streams every stage tick with a timestamp and the duration since the previous one (the planner's stages, post, verify, simulate per program, the goal check), kept for the run and saved beside the run record; a simulate-only press continues the generate's log instead of erasing the stages that made the program. A cutter running on another diameter's feed row says so on its row — "feeds: borrowed from the 3.2 mm row — slow" — with the same words in the details.
- **One cutter list as rows, and the Job line is a count** (#1123 item 5): the duplicate paragraph under "Cutter ·" collapses to one count; the one list is rows — the program numbers a cutter serves, its case label and colour, flute and deepest cut.
- **One cycle figure from one source** (#1123 item 6): the Job panel and the Cut step quote the same cycle; the tradeoff line names what it compares (owned plan vs catalogue ideal).
- **The Fit-and-clamp card states the shelf fact, and the turn-stock expander waits for a cut** (#1123 items 7 and 16): "You're supplying this stock yourself…" becomes the shelf fact and is dropped when a mount is stated; the expander waits for a cut and counts only THIS package's finished programs.
- **The open job and a generated run survive a reload** (#1123 items 10 and 11): the workspace record restores the job and the section, and the run — programs, receipt, checks, verdicts — is kept in IndexedDB keyed by (job sha, build), restored while they match, with a build-changed note; a restored run is verified against the house's settled reads before Cut is offered (Generate never waits on that check). The shop's ETags are a diagnostic, never the key: a finished-programs write must not lose a run.
- **The Cut step re-reads the location while it is on screen** (#1123 item 12): a 10 s ETag poll, and the change wizard's close, refresh it. An equal ETag moves nothing (the same location object, no churn), and a dropped request keeps the last good record — a Wi-Fi blip cannot blank the machine on the Cut step or move the validator a run is keyed on.
- **Setups is its own Design group** (#1123 item 27): Plan registration / Re-plan / Use this plan used to render at the bottom of the Hold group, after "Waste board … Save as my setup"; the section now has its own group (Job, Cutter, Hold, Setups) with the setup count as its closed summary.
- **The Register card never silently runs a stored plan the planner no longer proposes** (#1123 item 28): when the live proposal differs from the approved plan, the card says what differs, shows the current proposal, and offers **Use the new plan** in place; it never silently runs the old one.
- **A bracket top-touch plan narrates no scan** (#1123 item 29): `summarizePlan` drops the scan clause entirely when a plan has no scans.
- **The Setup rows shed the machine tag, and a bracket job stops reading strip wording** (#1123 item 37): no stray machine tag on the rows, and the strips preset is the vise's — a bracket job no longer reads "Strips between the jaws".
- **The origin write records the tool number; Continue, Unlock and Home are on the Cut step** (#1123 items 31–35): after the cutter's `M491`, `M493.2T<n>` (the firmware's own form has no space) makes the program's `T1 M6` a no-op — without it the controller still held the probe and went `<Tool|>`; "Waiting for the cutter" has a Continue that sends `M490.2`; the alarm's Unlock (`$X`) and Home sit on the Cut step, not only in Manage; the fit step names the cutter; the strip names the fitted cutter rather than "T8888 · 3D probe".
- **The live view shows the uncut blank, not the finished simulation** (#1123 items 36 and 38): while a program or a probe owns the machine, the viewport draws the blank and the design's extents with the live tool at the machine's WPos — the finished simulation's swept stock and yellow path stay off until the machine is idle. A factual readout states positions only ("tool centre X 9.560, Y 15.300 · the design's extents (bounding box) span …: the tool centre is 0.216 mm right of the design's left edge"), never a verdict. Progressive removal driven by the controller's line is #1141.
- **A finished program no longer takes the screen** (#1123 item 39): the done card shows only when the release says every program is finished; otherwise the Release step's next press stays reachable — after a reload too, where the step rebuilds its pending list from the house's finished hashes and names the next program.
- **The registration survives a reload** (#1123 item 40): a registration is kept on the house's machine record, one memo per job setup, carrying the plan, the outcome, the measuredAt and the G54 X/Y the origin write left in the controller. On reload it is restored only while the machine's live G54 X/Y (`MPos − WPos`) still matches within 0.01 mm; a moved G54, an unreachable machine, a line without both positions, or another machine's answer restores nothing and says why, asking for a re-register. The restored line states the scope: X/Y verified, Z as written then.
- **The job-owned vacuum span is re-stated on every start** (#1123 item 41): after an alarm, the retry of program 1 ran dry because the runner left the vacuum to the file's own M331, which died with the alarm. `runProgram` now states M331 (and M331.1, the blower) before every program of a span that wants the vacuum — idempotent, never a toggle — and the end-of-program switch-off honours the span, the card's words coming from the same decision. The bench fact that closes #1060's open question: the Auto Blow is `M331.1`.
- **The running program's progress is on the Cut step** (#1123 item 42): while a program plays, the step states its percent and the time the controller's own `P:` reading implies ("Program 2 of 5 is 20 % done — about 20 s left"), honest at the edges (no percentage yet, 100 % reads "finishing", a paused run says when the time applies), and names the next program in cut order that needs a different cutter, skipping same-cutter and already-finished programs. Both lines clear at the bit-change pause, where the Change panel takes over.
- **The cutter checklist gates the first Load** ([#1127](https://github.com/SlyWombat/CaseMaker/issues/1127)): one interactive row per bit — located, or replaced with another OWNED cutter of the same shape and cutting diameter — keyed by the frozen package's hash, with the run's cutter list the same rows on both screens. Cut starts only when every bit is accounted for. The checklist is not a byte input: it is stripped from the fingerprint and every staleness compare, so ticking never stales a program and never calls a worker.
- **A program is stale only when its bytes change** ([#1132](https://github.com/SlyWombat/CaseMaker/issues/1132), #1123 item 30): approvals, any setup's registration, re-planning, the owned-vs-ideal choice and the Cut-strip toggles no longer stale a program — they re-freeze its stored setups instantly, with no worker, and the Cut screen names the changed thing and the honest cost before the press ("Regenerate — about N min (last Generate on this job)"). The bytes list is stock, items, cutters, facing and hold. A flipped setup's registration is no longer compared at all (its executor never reads the approved plan). Packages frozen before the upgrade migrate silently: the new fingerprint hashes the RESOLVED setups, so `legacyJobFingerprint` reproduces the old view verbatim and either hash is accepted; the store re-freezes such a package on open with the same programs and bytes. The one visible consequence: the Cut step's single clearance statement is keyed to the package hash, which that silent re-freeze moves, so it is asked once more for a job frozen before the upgrade.
- **A 3MF's components and build transforms are applied** ([#1131](https://github.com/SlyWombat/CaseMaker/issues/1131)): the reader parses the document's objects, their `<components>` references and the `<build>`'s items, and composes each build item as its component chain × the item transform × the vertices (3MF's point-on-the-left 4×3 affine, with the model's unit scaling the translation too). Nested chains compose; an object the build does not place is still read at its own place; a transform that is not twelve finite numbers, a component cycle and a reference to an undefined object are refused by name.

### Milestone 1 close-out — the rebuilt engine, the gate and the flip (2026-11-05 → 2026-11-09)

This block catches the changelog up with the Milestone 1 landings: the CAM rebuild on the model engine, the goal-check gate's versions, and the operator-facing fixes that followed. One entry per closed issue; test-only and internal-only closures are listed at the end with their reasons.

**The rebuilt CAM engine (cam/model).**

- **The model engine replaces the heightfield planner** ([#956](https://github.com/SlyWombat/CaseMaker/issues/956)): one CAM plans a goal mesh or STEP from a cutter-location surface — Z-level roughing, slope finishing, a cost-ranked cutter sequence and stay-down linking — ported from Kiri:Moto (MIT) with OpenCamLib as the algorithm reference; everything else in this list is a cell of it.
- **The cutter-location surface by drop-cutter** ([#957](https://github.com/SlyWombat/CaseMaker/issues/957)): flat, ball, bull and V cutters sample the goal triangles, and every operation reads that one CL surface.
- **Planar-face recognition** ([#958](https://github.com/SlyWombat/CaseMaker/issues/958)): pockets, islands, contour, rims and the curved remainder are recognised from the mesh or STEP the job carries.
- **Z-level roughing and rest** ([#959](https://github.com/SlyWombat/CaseMaker/issues/959)): stock minus the CL surface is roughed in levels, the rest is cut by CL difference, and feature pockets and the contour are cut with tabs.
- **Finishing by slope** ([#960](https://github.com/SlyWombat/CaseMaker/issues/960)): flat-following raster on shallow ground, the ball at a constant scallop on steep ground, pencil on the creases and a chamfer on the rims.
- **The cutter sequence chosen by cost** ([#961](https://github.com/SlyWombat/CaseMaker/issues/961)): the largest flat first, smaller flats for the rest, the ball to finish and the chamfer for rims — the plan a job posts is the cheapest it can prove.
- **Stay-down linking** ([#962](https://github.com/SlyWombat/CaseMaker/issues/962)): adjacent passes link without a retract, clearance is per region and the tour order is planned, not left to the post.
- **The rebuilt engine's job model and UI seams** ([#963](https://github.com/SlyWombat/CaseMaker/issues/963)): features, sequence and linking read in the operator's words on the panel and the sheet, and the budget presses are gone.
- **The rebuild is integrated and the old engine removed** ([#966](https://github.com/SlyWombat/CaseMaker/issues/966)): every reference card is re-scored on the model engine, and the heightfield planner no longer ships.
- **A goal taller than its blank is cut to the stock bottom** ([#1003](https://github.com/SlyWombat/CaseMaker/issues/1003)): the plan knows the stock bottom, so a goal that reaches past the blank frees at the stock's underside instead of cutting below it.
- **One Z datum inside planModelCam** ([#1018](https://github.com/SlyWombat/CaseMaker/issues/1018)): the mesh is shifted to stock-top-relative at the door and the ± z0 / zOffsetMm shims are deleted — the class behind the earlier datum faults.
- **The goal's mould flag, its sides and its underside floor cross the model seam** ([#1005](https://github.com/SlyWombat/CaseMaker/issues/1005), [#1006](https://github.com/SlyWombat/CaseMaker/issues/1006)): moulds, two-sided jobs and an underside floor are planned by the model engine, not only stated by the job.
- **The goal-check report and surface facts ride the model path** ([#1007](https://github.com/SlyWombat/CaseMaker/issues/1007)): the run result carries the check's report, so the Cut card and the receipt can state the verdict.
- **closeOpenSheet no longer overflows the stack** ([#1015](https://github.com/SlyWombat/CaseMaker/issues/1015)): a 125k+ triangle mesh (the 12 MB dragon) reaches CAM instead of dying at the door.
- **The manifold-3d glue's per-vertex leak is patched** ([#1022](https://github.com/SlyWombat/CaseMaker/issues/1022)): each polygons→CrossSection conversion and each toPolygons stops leaking, ending the per-cell wasm abort.
- **The per-cell Clipper form no longer aborts under accumulated state** ([#1024](https://github.com/SlyWombat/CaseMaker/issues/1024)): the captured call replays clean in a fresh process, and the planner's cells no longer inherit a poisoned state.
- **A non-finite vertex at the mesh door is refused before the booleans** ([#1029](https://github.com/SlyWombat/CaseMaker/issues/1029)): one NaN/Infinity in a user's STL or 3MF no longer reaches Clipper or Manifold.
- **A knife-edge shared by four triangles is split, not refused** ([#993](https://github.com/SlyWombat/CaseMaker/issues/993)): the organizer's shipped STL opens, with the non-manifold edge split rather than the door refusing it.
- **Fillets are read as fillets, not modelled chamfers** ([#994](https://github.com/SlyWombat/CaseMaker/issues/994)): the wall test reads where the wall contact is, so a curved rim is not cut as a V along its curves.
- **A user's STEP keeps its B-rep identity** ([#991](https://github.com/SlyWombat/CaseMaker/issues/991)): the door no longer drops faceId and tessellates at display defaults, so the cards represent the app.
- **An SVG stroke with a width is a region** ([#968](https://github.com/SlyWombat/CaseMaker/issues/968)): the painted band is cut, not its centre line — the coasters and badge reference cards.

**The goal-check gate.**

- **The goal cut-into check runs in the app** ([#948](https://github.com/SlyWombat/CaseMaker/issues/948)): the swept top of a goal program and the goal heightfield reach the oracle, and 3D goals are judged, not just 2.5D.
- **Gate v6 — a cut-into cell on a vertical step can be excused on proof** ([#996](https://github.com/SlyWombat/CaseMaker/issues/996)): corners span the step and the swept centre is not below the design's low side; the count is printed, and SIMULATOR_VERSION moves to 6.
- **The STL row is gated on all seven lines, as the STEP row is** ([#995](https://github.com/SlyWombat/CaseMaker/issues/995)): both rows must pass, so a mesh job is held to the same verdict as a B-rep one.
- **Gate v8 — every excuse is a proof bounded by the goal's own relief** ([#1092](https://github.com/SlyWombat/CaseMaker/issues/1092)): the wall and border cells lose their unconditional excuse, the silhouette gets its own proof with an inward witness, and a budget refusal is stated (`rest-region-over-budget`) rather than silently thinning the plan. The same land fixes the rest pass: a rest level is two spaces, not one mask — the previous cutter's stamp dilated by its own disc against the rest cutter's drop-cutter tip over the goal (one neutral `dropTip` module and each region's exact flat tip field) — so j29's buried discs are gone (0 % cut-into) while the strips beside its walls are cut, and set B's top p5/bottom p2 do more of the rest work they owed (leftover −31 %, cut-into unchanged).
- **The edge-break allowance seeds only from design walls** ([#1064](https://github.com/SlyWombat/CaseMaker/issues/1064)): a stated rim chamfer no longer excuses V bevels on interior pocket lips.
- **ref-toolholder's plan covers its goal's top surface** ([#1075](https://github.com/SlyWombat/CaseMaker/issues/1075)): the 86.93 % standing reading is fixed, and the card reads the plan's real coverage.

**Feeds, cutters and the owned set.**

- **The owned plan's house is the owned set** ([#1041](https://github.com/SlyWombat/CaseMaker/issues/1041)): built-in and catalogue twins no longer enter the "owned" M1 tray plan beside their `inv:` rows.
- **A chosen unowned tool is stated as such** ([#1042](https://github.com/SlyWombat/CaseMaker/issues/1042)): an unowned cutter entering the owned plan's house is named, never silent.
- **The cutter plan picks from the owned set and judges the ball by reach** ([#1051](https://github.com/SlyWombat/CaseMaker/issues/1051)): no catalogue ball the shop does not own is named for a 3D goal.
- **The wizard's reach gate judges the ball by the goal's depth** ([#1037](https://github.com/SlyWombat/CaseMaker/issues/1037)): the M1 tray passes with the owned set (the ball's 4.2 mm reach, not the goal's full depth).
- **One candidate with no feeds row no longer refuses the whole job** ([#1044](https://github.com/SlyWombat/CaseMaker/issues/1044)): the plan proceeds without that cutter instead of refusing the aluminium job.
- **The model plan sees Makera's catalogue rows** ([#1047](https://github.com/SlyWombat/CaseMaker/issues/1047)): the caller's feed rows reach the worker, so the plan's numbers are the catalogue's.
- **The ideal plan reuses the owned plan** ([#1049](https://github.com/SlyWombat/CaseMaker/issues/1049)): a press no longer re-plans the owned plan (~450 s saved on the tray).
- **Every cutter gets its own feed, step-down and RPM** ([#990](https://github.com/SlyWombat/CaseMaker/issues/990)): a non-primary cutter no longer inherits the primary flat's numbers.
- **The ideal plan picks the finishing ball by outcome** ([#986](https://github.com/SlyWombat/CaseMaker/issues/986)): the catalogue's largest ball no longer bridges the panther when a smaller one finishes it.
- **The cutter picker hides the built-ins when the shop has its own records** ([#1065](https://github.com/SlyWombat/CaseMaker/issues/1065)): the list matches the house set.
- **Probes are not cutters** ([#1063](https://github.com/SlyWombat/CaseMaker/issues/1063)): instrument records are excluded from the house set and the picker, with one aggregate statement.
- **The app and the CLI see one owned list, and a ball tie takes the reach margin** ([#1111](https://github.com/SlyWombat/CaseMaker/issues/1111)): the owned set is in a canonical order (tier, then key) on both doors, so the M1 tray's finish picks the same cutter from the app and the CLI; two balls equal on the rank's keys are separated by `fluteLength − deepest cut ≥ reachMarginMm` (the shop's setting, 1.0 mm recommended), so the 22 mm ball wins p5 where the 10 mm one would have had 0.387 mm of margin. Other same-diameter picks keep their old order, and the row states the provisional choice "by key, pending #1114".
- **An owned-only run names the ball that would take the leftover** ([#1027](https://github.com/SlyWombat/CaseMaker/issues/1027)): "about ⌀N" from the leftover's own inscribed diameter, with both thresholds' provenance.
- **A pocket no owned cutter can enter is stated unreachable** ([#1019](https://github.com/SlyWombat/CaseMaker/issues/1019)): the mould side's floor patch no longer refuses the whole job.
- **Pockets too small for any flat or ball get the V bit already in the set** ([#975](https://github.com/SlyWombat/CaseMaker/issues/975)): the tray's digits are cut.
- **Clearing with no flat in the set falls back to the ball** ([#982](https://github.com/SlyWombat/CaseMaker/issues/982)): the job is planned, not refused.

- **Epoxy tooling board is a stock material** ([#1066](https://github.com/SlyWombat/CaseMaker/issues/1066)): the wizard's material list offers it, Makera's `Epoxy Tooling` feed rows answer for it, and the run sheet prints the material in the app's own words ("100 × 100 × 10 mm Epoxy tooling board").

**Cutting correctness on the model engine.**

- **A pocket op no longer cuts 22 mm of air under the material above its level** ([#970](https://github.com/SlyWombat/CaseMaker/issues/970)): the elephant's pocket stays in its pocket.
- **A complex pocket's rim stays closed at branch points** ([#974](https://github.com/SlyWombat/CaseMaker/issues/974)): the rim chain no longer leaves an un-chamfered opening.
- **Skim joins follow the radius** ([#978](https://github.com/SlyWombat/CaseMaker/issues/978)): a staircase point no longer puts the flat's disc over neighbouring material.
- **planModelCam has a size pre-flight guard** ([#981](https://github.com/SlyWombat/CaseMaker/issues/981)): an oversized plan is measured before it is attempted.
- **The finish scallop seat no longer receives a step-over or an allowance** ([#985](https://github.com/SlyWombat/CaseMaker/issues/985)): the seat is a tolerance, and the finish reads it as one.
- **A skirt-closed relief no longer demands a contour** ([#987](https://github.com/SlyWombat/CaseMaker/issues/987)): a synthetic outline is not a design edge, and the job posts its two programs.

- **The Simulate form asks which cutter a file was cut with, when two matching rows come from different tiers** ([#316](https://github.com/SlyWombat/CaseMaker/issues/316)): a `.nc` header's TOOL record answers "which of my cutters is this?" three ways (`engine/cnc/headerMatch.ts`), and when one of those rungs matched rows in **two or more tiers** — an owned `inv:` row and the `cat:` row it was registered from, which carry the same vendor `g_ID` and the same lengths because registering an item materialises the catalogue tool as its snapshot — neither row is entitled to win and the old code silently took one. The match now comes back `suggested` with BOTH rows as `candidates`, ordered by `TIER_ORDER` (`owned` › `yours` › `catalogue`), and the form applies **neither**: the Tool select holds nothing and the panel puts the question, one button per candidate, each named with the word the Manage picker already tags its tier with. A remembered key is applied only while it is still among the rows that match that signature today, which is the whole of the clearing rule: **Forget** on the row and a catalogue sync that changes a candidate both end by refreshing `toolRegistryStore`, so the pick lapses with nothing to subscribe to — and it **lapses rather than being deleted**, because a service that is merely unreachable refreshes the registry to built-ins only, and a self-cleaning map would then destroy the user's picks to punish a network hiccup. ### Fixed

- **A write to the house service now has to come from the app's own page** ([#375](https://github.com/SlyWombat/CaseMaker/issues/375)): `/api/v1` is served without authentication on purpose — the LAN is the trust boundary for tools, inventory, feeds and cuts (decision 33) — but "a browser" and "a browser the app served" were assumed to be the same client, and they are not. A page on **any** website, open in the user's own browser, can POST to `http://127.0.0.1:<port>/api/v1/import`: it is a CORS *simple* request, so no preflight is ever attempted, and `import_house` takes the raw body and parses it by hand — and that endpoint **replaces the whole house document**. `POST /api/v1/catalogue/sync` needs no body at all, and a rebound hostname is the same attack from the other side, because the browser then believes the request is same-origin and no provenance header disagrees. All of it now passes one guard (`guard.rs`), applied once over the merged `/api/v1` router in `server.rs` and before the SPA's routes — so an endpoint added to either module later is inside it without anyone remembering to add it, while the pages, which have no provenance to judge, are outside. Three questions, each of which a page on another site cannot answer: `Host` must name this server (`localhost`, an IP literal, or the name `config.json` is configured to serve under, which is what a LAN user who reaches the app by a machine name needs); `Origin` must be absent, or exactly `http://` plus that same `Host`; and a request that **declares** a body (`Content-Length > 0` or `Transfer-Encoding`) must call it `application/json`, the one type a cross-origin page cannot send without a preflight this server never answers. Refusals carry the service's own `{"error": …}` shape in every case, including the 415 that axum's `Json` extractor used to return in plain text for two of these endpoints — those reach the user as a reason instead of as "somebody other than the service answered". Nothing about the LAN case changes: a browser pointed at the app's own address still writes the house, which is what decision 33 is for, and the settings endpoint's loopback-only peer check (decision 35) stays exactly where it was. The body rule is phrased from the request's framing rather than unconditionally because of what the browser actually sends, observed rather than argued: the `text/plain` POST arrives typed, a `TypedArray` body arrives with a `Content-Length` and **no** `Content-Type` at all, a bodyless write arrives with `Content-Length: 0`, and a same-origin POST from the app's own window carries an `Origin` equal to `http://` plus its `Host` — so demanding the type unconditionally would refuse the app's own client, and refusing only a *wrong* type would let the byte-array body through. Three details of that rule were sharpened in review: a `Host` that states **no** port names the scheme's default, so it is this server only when this server is on port 80 — reading "no port stated" as "our port" left a portless `Host` as the one way past the port check; a present `Origin` this server cannot read is now its own refusal rather than being folded in with "no origin", which is the one bypass that distinction existed for; and the settings routes apply the guard themselves as well as carrying it from the merged router, so a settings write is guarded wherever that router is mounted. The guard stays a rule about **writes**, and that is a limitation stated rather than an oversight: a rebound name is same-origin to the browser on a read as much as on a write, so it can still read every read this API answers — `/api/v1/export` and the whole house document included — which is a copy to take elsewhere rather than a way to change the house (decision 33 carries the note).

- **A restart is no longer lowered through the Z1 when the load it restarts had no machine** ([#367](https://github.com/SlyWombat/CaseMaker/issues/367)): `simStore.generateRestart` resolved its machine as `MACHINES[lastLoad.machineId ?? ''] ?? Z1`, so a load with no machine silently became a Z1 — while the load that precedes it resolves **no** machine for a null id, and the two halves of the same load disagreed about which machine they were on. The difference is not cosmetic: a machine-present sweep synthesises tool changes, TLO calibration and G28 clearance expansion and tests every move with `insideEnvelope`, and the restart generator writes the profile's id into the emitted program (`;@MKR|MACHINE|id=z1`). A restart of a machine-less load could therefore carry macro steps, envelope errors and a machine header the run it restarts never had. The generator now refuses a load with no machine, in the same shape and for the same reason as the stock refusal beside it: what the load did not have, the restart must not invent. An unknown id cannot reach the generator at all — `session.load` refuses it before any frame, which leaves `stepCount` at 0. Latent rather than user-visible (every app caller passes a real id today, and the specs that load with `null` do so deliberately), but pinned by a spec that loads machine-less, and gone from the one line that invited the assumption.

- **The "App port" field now reaches `config.json` — the file the app actually starts from** ([#372](https://github.com/SlyWombat/CaseMaker/issues/372)): the desktop settings dialog's port field (and the `Allow LAN access` checkbox beside it) wrote `casemaker.settings.v1` in the webview's own storage, and **nothing on the Rust side read it** — `lib.rs` reads `config.json` and `--port`, so the field had never changed the port the app binds. It was dormant before #312 and actively misleading after it: the port is now fixed and a taken one is a refusal with a dialog, so a control that looks like the way to answer that dialog, and is not, points the user at the wrong fix. Both settings now read and write `config.rs`'s `AppConfig` over `POST /api/v1/config`, served by the app's own embedded server beside the house service, and the section shows the numbers the file holds instead of what was last typed. A change applies at the **next** start and says so, because a live rebind is impossible: the window is loaded from `http://127.0.0.1:<port>`, so the port is part of the app's **origin** and every origin-keyed store — settings, library, run records, the machine's own calibration — would be left behind while the page kept its old storage (that is #312's rule, and the panel now repeats the refusal's own warning exactly while the saved port and the serving port disagree). The write is **loopback only**: these are the host process's settings, and a client that can rewrite them decides whether the host starts at all, so a browser on the LAN is shown the same numbers and the same dialog and is refused in the service's own sentence (decision 35; the house's own data stays unauthenticated, decision 33). Loopback was not enough on its own and this is worth stating: a page in the user's **own** browser also arrives from loopback, so a peer check by itself would have let **any website** write these settings with a `text/plain` POST that needs no preflight. A write must therefore also *be* the app — `application/json`, an absent `Origin` or the app's own page, and a `Host` naming the app itself (which is what a rebound name cannot do) — and a save now lands by rename, so a torn write cannot leave the next launch reading the defaults with its `host` gone. `settingsStore.port`/`bindToAll` and the `setPortSetting` test hook are gone with it — the store's shape is asserted to carry neither, since a copy in an origin-keyed store is the defect itself. A body that names a field the endpoint does not own is refused rather than ignored, so a client sending `host` is never told its save went through.

- **A plate tab screw now seats instead of bottoming out in its pilot** ([#371](https://github.com/SlyWombat/CaseMaker/issues/371)): the pilot depth was a literal 21 mm, so with the plate clamped onto its ledge the M5 × 25 the hardware list names ran out of hole about a millimetre before its head reached the seat, and a screw that bottoms out jacks the plate back up. The pilot is now derived from the screw (25 mm under the head, plus 1 mm spare, less the tab's bearing floor), and a test seats the real screw as a solid in the clamped assembly on every tab, both plates, every fit rung and two depths. The hardware list now says **button head**, which is what the counterbore is cut for; a socket cap stands about 2 mm proud. Print-affecting: the side panels' tab pilots are 3.2 mm deeper.

- **A test run no longer rewrites the documentation screenshots** ([#370](https://github.com/SlyWombat/CaseMaker/issues/370)): `tests/e2e/slot5-closeout-qa.spec.ts` wrote its ten captures straight into `docs/assets/slot5-*.png`, so every routine e2e pass left the tree dirty with byte-different images of the same screens — twice seen and twice restored by hand, and a commit sweep or a deploy could have carried the changes along with nobody having looked at them. Screenshots are documentation, not test output: the captures now go to Playwright's own output dir (`testInfo.outputPath`, under the gitignored `test-results/`) and those tracked files are rewritten only by a deliberate docs refresh, `UPDATE_DOC_SHOTS=1 npx playwright test tests/e2e/slot5-closeout-qa.spec.ts`, which is stated in the spec's header and in CONTRIBUTING's test contract — the doc says it because the next spec to take screenshots should not have to rediscover it.

- **A port that cannot be had is a refusal, not a silent move to another origin** ([#312](https://github.com/SlyWombat/CaseMaker/issues/312)): a desktop build's `localStorage` is keyed by ORIGIN, and the origin includes the port, so anything that moved the port took every store with it — `casemaker.settings.v1` (the saved vise and stack, the machine calibration), `casemaker.library.v1`, `casemaker.machine.v1`, the engrave job and the run records. `server.rs` used to fall back to an **ephemeral** port when the configured one was taken, and `lib.rs` then loaded the webview from whatever it got, which is a different storage partition: a second launch, or any foreign process on the port, turned a working app into one that had forgotten everything — no error, and the user's data still on disk under a port they no longer knew. The fallback is gone. `AddrInUse` now comes back as an error naming the port and where the data lives, and `lib.rs` shows it in a native dialog and exits instead of falling through to `tauri://localhost` — another origin, and the same silence from the other side. A second Case Maker launch never gets that far at all: `tauri-plugin-single-instance`, registered first as it requires, hands the running instance its argv, raises that window and exits before any window, store or listener exists. The house lock (#321) stays as the backstop for a process the plugin cannot see, which is also why its comment no longer claims the port fallback as its reason to exist. `--port` still works and still starts, but the message says what it costs: a different origin and an empty app. The in-app "App port" field was never connected to any of this and is now its own issue ([#372](https://github.com/SlyWombat/CaseMaker/issues/372)) — today it changes nothing but the value it stores, which after this change is worse than useless, since it looks like the way to answer a port-busy refusal and is not.

- **The rack's plate-tab joint has a designed THICKNESS clearance, and #153's fit ladder reaches it** ([#356](https://github.com/SlyWombat/CaseMaker/issues/356)): the ledge's z opening was exactly `TAB_T` — a nominal tab in a nominal opening, with nothing but the printer's own error between them — so the printed network-closet rack's tabs bound on their thickness (0.2 mm off the tab's inner face freed it by hand) as well as their width the designed 0.3 mm/side did not, which is why a looser `rack.fit` alone could not rescue that joint. The joint now carries `TAB_Z_SLACK` (0.3 mm), the z twin of `TAB_SLACK`, and the same ladder rides it, so the whole thickness clearance is `TAB_Z_SLACK + fitRelief(rack.fit)` — 0.3 / 0.4 / 0.55, exactly the ladder the width already has per side. It is shared between the two printed halves, split so `snap.ts`'s rule holds — the relief goes on the CUT, never on both halves: the tab gives up a **fixed** `TAB_Z_SHAVE` = 0.2 mm on its INNER face only, and the LEDGE opens by `TAB_Z_OPEN` = 0.1 mm **plus the whole ladder** — the bottom ledge reaching UP off the stacking foot the tab seats on, the top ledge floor dropping DOWN away from the flush top face. The shave is one WHOLE 0.2 mm layer, not half of one: the plates print counterbores UP, so the tab's inner face is the BED face, and a 0.1 mm step there is half the first layer — the slicer samples that layer at z = 0.1, exactly on the face, so it either rounds the shave away or starts the tab on layer 2 as a 12 mm cantilever floating over the bed. 0.2 mm is the maintainer's own hand fix on the bound rack. The outer face is still the datum: it stays flush with the plate, so the 3 mm screw-head seat is untouched and the bearing floor under the counterbore is 1.8 mm. That split has a consequence worth knowing before you print: **the ladder lives in the sides' ledge cut**, so reprinting only the plates against sides you already have buys just the tab's fixed 0.2 mm — the two looser rungs cost two new panels. Both screw starters' mouths ride the ledge they open onto, and the lightening keep-outs and the fan path's re-cut of the same ledges move with them; the fan path's two hand-copied `box` calls are now one shared `ledgesAt`, so a fan strip and the panel body can never carve the notch to different sizes. Nothing moves in x or y, and `rack.fit` absent still compiles the as-designed joint — not byte-identical to pre-#356, because the clearance **is** the design now. The one-piece export offered next to the parts welds the plates to the sides instead of fitting them, so it now compiles the frame with this joint **nominal** (`tabZJoint`): the new clearance is a 12 mm sheet of air over every tab's inner face with solid rail above it and the deck below, which no weld reaches, and a part printed as a unit has no fitting to do — leaving it in would have exported an internal crack, half a millimetre of it at a loose rung. Nothing else about the fused frame changed. The rack-tab fit coupon (#157) could not feel a thickness bind at all, since its rungs moved only the slot's width and reach; its ledge slices now open taller per rung against the one printed tab, which stays fixed on purpose so a single tab still grades all three rungs, and the coupon's note now says both what the rungs measure and what they cannot: the ledge slice prints rack-z as print-z where the real panel lies flat, so the z grade is layer-quantised and two adjacent rungs can print as one face — the slot's WIDTH is the coupon's precise grade.

- **A jaw limits only the line that can reach it, and the badge's seeded name is no longer charged for the jaws beside it** ([#369](https://github.com/SlyWombat/CaseMaker/issues/369)): #365 made the **void** bound per item and left the **jaw** bound blank-wide, so on the badge template every label was advised the 0.905 mm a line standing *beside* a jaw allows — including the seeded `Name`, laid in the free band and stopping 6.9 mm short of the fixed jaw against a 3.5 mm reach. A jaw now binds only the items whose own extent comes within its reach, the same per-item rule and the same measured ink box #365 established: the reach is the vise's own uncertainty plus the job's jaw clearance plus the cutter's radius (2 + 1 + 0.5 mm on the shipped default), and it is judged on the line's box projected into the jaws' frame, so a rotated line is read the way the blank sees it. The seeded badge line therefore takes the blank's own colour split — 0.8 mm boundary plus one 0.2 mm layer, the 1.0 mm **reveal** — where the blank-wide check had held it to the jaws' 0.905, a value that lands inside the split's own ±0.2 mm band and came back up as a 0.6 mm **surface** floor. The clause names the jaw that binds, with the gap and the stock-provenance arithmetic behind it (`the line comes within 2 mm of the fixed jaw; the stock stands 1.905 mm above the jaw tops and a floor has to stay 1 mm clear of them`), and an exact tie goes to the first jaw the envelope declares so the sentence cannot flicker between two; a line clear of both says so rather than passing over them in silence. The reach is judged on the line's own MEASURED ink box, off the face the layout was made from, with the documented upper-bound estimate standing in only where that face is not parsed yet — until #394 it read the estimate in every case, which let the estimate's own width decide the answer. The gap it reports is measured to a box that CONTAINS the line's ink box, which is why the clear-of-both clause reads `at least`. Two readers follow the same reach: `stock-proud-too-small` now fires only for a cut that actually comes within it, and the run sheet states its "stop below" value only where one does, saying in words that the jaws set no limit on a job where none does. The reach is the vise's own uncertainty plus the cutter's radius; the job's jaw clearance is not in it (#394 took it out), because the clearance is a Z rule charged to the depth. The stop line is the stricter reading of the same rule: it fires only where the cutter's own disc, no band allowed for, really comes over a jaw face, and it names the cut and the jaw that trip it.
- **The printed cycle estimate timed every move at a guessed 3000 mm/min and ignored acceleration** ([#281](https://github.com/SlyWombat/CaseMaker/issues/281)): one constant served every machine and every move, and on the Z1's 150 mm/s² the accelerate/decelerate terms are most of a short move, so a job made of them read about half its real time. The estimate now runs on the machine profile's own rapid model — the controller's X/Y 1200 mm/min, Z 600 and 150 mm/s², read off the Z1's config (`config-get sd`, 2026-10-07) and bracketed by a stopwatch sample of an 88.4 mm X-only rapid — and times a move through a trapezoid: `d/v + v/a` when it is long enough to reach its rate, `2·√(d/a)` when it is not, with Z's own half-rate ceiling for a Z-only rapid. Cutting is timed per contiguous feed run, not per chord, because the planner carries speed across the junction between two cuts and a pocket here is cut in 0.05 mm segments; rapids are a stop at each end, so each is timed on its own. The panel's row, the run sheet and the post's `;@MKR|TIME` all read the one function, so they cannot disagree, and the sheet and the `.nc` header now say where the numbers came from in words. It stays a planning figure, not a measured cycle time: `#208 D3`'s timed air run — feeds and rapids compared as two portions — is what closes it.
- **A void limits the line that is over it, not every line on the blank** ([#365](https://github.com/SlyWombat/CaseMaker/issues/365)): the recommended depth took the shallowest void limit **anywhere** on the blank, so on the badge the seeded name — laid in the free band *beside* the magnet pocket — was advised the pocket's 0.51 mm it was nowhere near, when the jaws over that band allow 0.905 mm. The limit is now per item: it comes from the voids the line's own extent reaches, computed analytically per void kind (a rect, a circle, a slot as its two end discs, a polygon as its bounding ring — all conservative where the outline is rounded, and the honest superset everywhere, since the verifier's own floor is positional at toolpath points that lie inside the ink box). The extent is the line's whole ink box, measured from the same face the layout was, with the documented upper-bound estimate (`ESTIMATED_ADVANCE_EM`, and a new `ESTIMATED_HEIGHT_EM` beside it) as the fallback when that face is not parsed yet — the height was the one nobody expected to need a constant, and the old fallback of a bare cap height was not an upper bound at all, so an unparsed face could miss a void the real glyphs would walk into. Both constants are claims about the FACES and were re-measured as such: scanned over every glyph of every bundled face the widest is the per-mille sign (`‰`, 1.91 of cap per character as an ADVANCE rather than as ink) and the tallest is a SPAN across two letters — `Ắ` over `ķ` in IBM Plex Serif bold, 2.06 of cap, and still 2.02 without the Latin Extended-B pair — not the shading block `▓` (1.93) that a single-glyph reading picked up, which belongs to the box-drawing branch (U+2500–259F) the measurement leaves out. The earlier 1.25 was measured over a widest capital and 1.75 over `Åg`, and the first correction's 2.0 was still pinned by single glyphs and homogeneous lines, so none of the three held; a spec now typesets every glyph of every face — and the pair that puts a face's highest ink over its lowest — and fails if either constant stops bounding them or grows slack. The fallback is named on screen where it is used, so the advice can only move deeper later, never shallower. And the seed paths MEASURE rather than assume: the wizard's hand-off and the panel's two buttons await the labels' faces before they seed, where a badge taken cold had seeded the estimate's 5 mm cap against the 8 the panel's own rows show for the same line. One number, three readers: the store's re-depth walk, the panel's row and the run sheet all ask `voidLimitForItem`, and the per-item limit can never disagree with the region scan the generator runs (`bindingVoidsByRegion`) — pinned by specs that compare the two where the box lies wholly inside one void, and, where the box is a superset of the ink and so reaches a void the ink does not, that its limit is the stricter of the two. The advertised pocket clause is unchanged where a line really is over a void.

- **Rack mid bearing pad widened to 46 mm** ([#143](https://github.com/SlyWombat/CaseMaker/issues/143)): the two end tabs are each pulled onto their stacking foot by an M5, but the mid tab has no screw at all, so bearing is its whole fixing. At the end-foot length of 30 mm the pad ran out only 4 mm past each end of the 22 mm tab; it now leaves 12 mm.
- **Save as… and Load threw "Illegal invocation"** ([#144](https://github.com/SlyWombat/CaseMaker/issues/144)): the File System Access pickers were handed back as bare function references and called as methods of a plain object, so `this` was not `window` and Chrome's binding refused. Export was unaffected, which is why STL export worked and Save as… did not.
- **Rack fan mounts no longer close the vent windows** — a fan was carried on a full-thickness strip spanning the panel, and even lightened the strip left `POCKET_SKIN` across every window it crossed, so the panel came out closed exactly where air was meant to move. With a fan on each side (one pushing, one pulling) the windows are the intake and exhaust path. The mount is now a pad carrying the bolt circle, hung off the nearest structural members by two rails. Measured on full-thickness line-of-sight probes: the strip closed 30 % of the side panel's open area at sample size (16 % on a tall rack), the pad and rails close 9 % (6 %) — most of which is the pad the fan bolts to. Material added per fan drops to 44.2 cm³ and is now the same on every rack shape (was 62.3–100.8 cm³).

- **Rack fan strip no longer thins the screw bosses** — the lightening pockets inside a fan strip are blind cuts from the outer face, and nothing kept them clear of the accessory screw columns they crossed. Every column inside the fan band lost ~70 % of its boss (821 → 244 mm³) and was then re-drilled, so the hole looked right and bit into ~1 mm of skin. The pockets now carry the same boss keep-outs the panel's own lightening uses. This was the reported "crowding the screw posts".

- **Rack side fans: mirrored panel got no cutouts** — the fan cuts computed their own lateral start as `xr(-OVER, 0)`, which mirrors to `[width, width + 1]`. On the right-hand panel every cutting cylinder therefore began on the outer face and ran away from the part, so adding one fan per side produced one working panel and one solid wall. The cuts now share `holeX`/`holeLen` with the screw columns, which mirror correctly.
- **Rack fan mount no longer spans the full height** — the mounting strip always ran rail to rail, so a tall rack paid its entire height in solid material for a local mount and swept a whole screw column into the strip on the way past. The strip now takes whichever span is shorter, height or depth: fan cost on a 28-slot rack drops from 100.8 cm³ to 62.3 cm³ and stops tracking rack height at all. Squat, deep racks still get the vertical strip. A full-depth strip crosses the rear anchor column, so that column is now re-drilled through the strip alongside the front and mid ones.

- **Smart-cutout pre-pass standoff omission** ([#43](https://github.com/SlyWombat/case-maker/issues/43)): `engine/compiler/smartCutoutLayout.ts:44` was computing `cutoutTopWorldZ` without `defaultStandoffHeight`, so the bridge-thinning check never fired after issue #28 propagated standoff into `ports.ts:50`. Smart-layout now matches the actual cutout Z. Issue #17's printability check works again.
- **Screw-down validator standoff omission** ([#44](https://github.com/SlyWombat/case-maker/issues/44)): `engine/compiler/validation.ts:42` was computing `componentTopZ` without standoff while `boardTopZ` included it, biasing every collision check by exactly one standoff. Real `+z` component / lid-post collisions now flag.
- **VESA mount holes pierce non-`-z` faces** ([#45](https://github.com/SlyWombat/case-maker/issues/45)): `engine/compiler/mountingFeatures.ts::generateVesaMount` was emitting Z-axis cylinders for every face. New `axisCylinder(facing, length, radius, segments)` primitive in `engine/compiler/buildPlan.ts` orients the through-hole along the face normal; VESA holes on `+y`/`+x`/`-x` faces now actually pierce the wall.
- **`computeShellDims` HAT-blind callers** ([#46](https://github.com/SlyWombat/case-maker/issues/46)): every consumer (`lid.ts`, `snapCatches.ts`, `displays.ts`, `antennas.ts`, `ventilation.ts`) now threads `hats` + `resolveHat` through to `computeShellDims`. The signature drops its optional defaults so the type system catches future omissions. `coords.ts` gains `pcbTopZ`/`pcbBottomZ`/`cavityOriginXY` helpers as the canonical Z-formula source.
- **Tauri CSP no longer blocks LAN-bound origin** ([#47](https://github.com/SlyWombat/case-maker/issues/47)): the embedded HTTP server now sends a `Content-Security-Policy` header on every response that uses `'self'` instead of hard-coded loopback hostnames; `tauri.conf.json` mirrors the same policy. The `--host=<LAN IP>` flag and the installer's `/HOST=` option now produce a working SPA, not just a working bind.
- **Removed `'sliding'` joint references** ([#48](https://github.com/SlyWombat/case-maker/issues/48)): `CasePanel.tsx` joint dropdown, `lidPostsAcrossJoints.spec.ts`, and the e2e `'sliding lid'` test now reflect the three-joint enum (`flat-lid`, `snap-fit`, `screw-down`). E2e test rewritten to assert the schema's preprocess-coercion of removed values.

### Added

- **Features panel** ([#49](https://github.com/SlyWombat/case-maker/issues/49)): new `FeaturesPanel.tsx` in the sidebar exposing the six engine domains that previously had no UI: display selector + framing toggle, antennas (add/enable/type/facing/remove), fan mounts (size/face/grille), text labels (text/face), mounting features (4-corner-tabs / VESA presets, enable, remove), snap catches (per-wall list with uPosition, only shown when joint is snap-fit), and a recessed-lid checkbox. Replaced with the actual 3.5mm audio jack and the right-edge MIPI camera + DSI display flex connectors. The DMX template (and the Uno DMX template) was also pushing HAT placements with `ports: []`, which silently dropped the XLR cutouts; both now auto-fill via `autoPortsForHat`. The Giga template additionally applies a Mega-form-factor x-offset so the Uno-form-factor shield sits over the host header column, not in free air.
